# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ClaudeX — a multi-agent AI collaboration workspace (Next.js App Router, React 19, TypeScript strict, Tailwind v4). Currently at the scaffold stage: `src/app/page.tsx` is a placeholder and the only test is an infrastructure smoke test. The README is unmodified `create-next-app` boilerplate (its `app/page.tsx` path is wrong; source lives under `src/`).

## Commands

```bash
npm run dev            # Next dev server on http://localhost:3000
npm run build          # production build
npm run lint           # ESLint (next core-web-vitals + typescript + prettier)
npm run typecheck      # tsc --noEmit
npm run format:check   # Prettier check (npm run format to write)
npm test               # vitest run (all tests once)
npm run test:watch
npm run test:coverage  # v8 coverage, text + html in coverage/

npx vitest run tests/unit/smoke.test.ts   # single file
npx vitest run -t "resolves the @/ alias" # single test by name
```

Run `lint`, `typecheck`, `format:check` and `test` before opening a PR.

## Architecture and config notes

- **Next.js 16** with `cacheComponents` and `partialPrefetching` enabled in `next.config.ts` — data fetching/caching follows the Cache Components model (`"use cache"`, Suspense boundaries for dynamic data), not the older `fetch`-cache/route-segment-config model. Typed route helpers like `LayoutProps<"/">` are globals generated by Next.
- **Tailwind v4** is wired through Turbopack: `*.css` files run through the `@tailwindcss/turbopack` loader (no PostCSS config, no `tailwind.config`). Styles are imported in `src/app/layout.tsx` via `globals.css`.
- **Path alias** `@/*` → `src/*`, defined in both `tsconfig.json` and `vitest.config.mts` — keep them in sync.
- **Tests** live in `tests/` (not colocated). Vitest only picks up `tests/**/*.test.ts` in a `node` environment — `.test.tsx` files are not collected and there is no DOM/jsdom or React Testing Library yet; component tests would require adding those and widening `include`. Coverage only counts `src/**/*.ts` (excludes `.tsx`).
- **Env vars**: copy `.env.example` to `.env.local`. Server-only secrets must not use the `NEXT_PUBLIC_` prefix.

## Team workflow rules

This is a two-person course project (graded on authentic Claude Code workflow and TDD history):

- One issue → one branch → one PR. Never push directly to `main`.
- TDD: commit the failing test on its own first, then the implementation. Never rewrite history to manufacture RED→GREEN evidence.
- Commits must **not** carry AI attribution (no `Co-Authored-By: Claude` trailers). Record AI usage in the PR description instead (tools used, rough AI %, human review done).
- Evidence (logs, test output, standups) must be real; mark gaps as "待补" rather than filling them in. Redact keys and local paths.
- Force-push, history rewrites and deploys need both teammates' confirmation.
